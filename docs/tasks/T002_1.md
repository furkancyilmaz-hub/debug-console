# T002_1 — Detay, drill-down ve form

Feature: [SP002](../features/SP002.md) · Repo: debug-console
Konum: `src/features/crud/`
Önceki: T002_0 · Sonraki: T002_2

**N+1 trafiği burada doğuyor.** Kullanıcı listeden detaya inerken naif uçlar
çağrılıyor — ayrıca bir şey yapmasına gerek yok.

## Adımlar

1. **Routing** — React Router kur. Rotalar:
   ```
   /proposals                 liste
   /proposals/:id             detay + müşterileri
   /customers                 liste
   /customers/:id             detay + ödemeleri
   /customers/overview        özet ekranı
   /analysis                  analiz sekmesi (F18)
   ```
   Sayfa yenilendiğinde aynı ekran açılmalı; bağlantı paylaşılabilmeli.
   Filtre ve sayfa numarası da query string'e yansısın (`?city=Ankara&page=2`).

2. **Uçların dağılımı** — farklı ekranlar farklı uçları kullanır, gerçek bir kod
   tabanındaki gibi. Ekranda hangisinin naif olduğu **yazmaz**:

   | Ekran | Uç |
   |---|---|
   | `/proposals` | `GET /proposals` |
   | `/proposals/:id` | `GET /proposals/{id}` + `GET /proposals/detail` |
   | `/customers` | `GET /customers` (arama: `/customers/search`) |
   | `/customers/:id` | `GET /customers/{id}/payments` |
   | `/customers/overview` | `GET /customers/overview` |
   | müşteri listesi "ödeme özeti" sekmesi | `GET /customers/detail` |

3. **`DetailLayout`** — üstte özet alanları (`DescriptionList` bileşeni),
   altta ilişkili kayıtların tablosu. `DataTable` yeniden kullanılır.

4. **Breadcrumb** — Teklifler › TEK-000123 › Müşteriler. Geri gezinme çalışsın.

5. **Yeni teklif formu** — `/proposals/new`:
   - Alanlar: teklif no, durum (select), düzenleme tarihi, toplam prim
   - **Doğrulama elle yazılır**, form kütüphanesi kurma:
     `type FieldError = { field: string; message: string }`
     - zorunlu alanlar, tarih formatı, prim > 0
     - alan `blur` olunca doğrula, submit'te hepsini doğrula
     - hata mesajı ilgili input'un altında, `aria-invalid` + `aria-describedby`
   - Submit sırasında buton `disabled` + spinner; çift gönderim engelli
   - Sunucu 4xx dönerse alan bazlı hatayı forma yansıt
   - Başarıda listeye dön ve listeyi tazele

6. **`useMutation` hook'u** — `useResource`'ın yazma karşılığı:
   `{ mutate, loading, error }`. Aynı iptal/yarış disiplini.

7. Detay ekranlarında da yükleniyor/boş/hata durumları — T17a'daki bileşenler.

## Doğrulama

- `/customers/:id` adresini doğrudan tarayıcıya yaz → ekran açılıyor
- Filtre uygula, sayfayı yenile → filtre korunuyor
- Formu boş gönder → alan bazlı hatalar çıkıyor, istek gitmiyor
- Submit'e iki kez hızlıca bas → tek istek gidiyor
- `/customers` sekmesinde "ödeme özeti"ne geç → `app_log`'da tekrarlayan
  `from payment where customer_id=?` satırları oluşuyor
